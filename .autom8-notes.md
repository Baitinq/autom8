# Investigation Notes

## Bug Found: Worktree-to-Task Mapping in status.go

### The Problem
In `src/cmd/status.go` lines 50-56, the code extracts task ID from worktree name by simply removing the last `-N` suffix:

```go
taskID := worktreeName
if lastDash := strings.LastIndex(worktreeName, "-"); lastDash > 0 {
    taskID = worktreeName[:lastDash]
}
```

This works for independent tasks: `my-task-1` -> `my-task`

But fails for dependent tasks: `test-child-1-1` -> `test-child-1` (WRONG, should be `test-child`)

### The Fix
The `baseTaskIDFromWorktree` function in `implement.go` (lines 164-182) does this correctly - it iterates through parts and matches against known task IDs.

**Solution:**
1. Move `baseTaskIDFromWorktree` from `cmd/implement.go` to `core/task.go` and export it as `BaseTaskIDFromWorktree`
2. Update `status.go` to use this function with the taskMap
